# 三地图原型 0.2.0

日期：2026-10-13。沿用设计文档v0.1的收费与使用规则，本轮继续开发地图接入和保存恢复，无需玩家立即试玩。

## 本轮实现

| 内容 | 变化 |
| --- | --- |
| 三地图接入 | 默认配置加入零号区、仓库区、农场镇，另识别农场镇南部。按原游戏的场景显示名键匹配，不写死未经验证的地图坐标。 |
| 站点生成 | 每个符合配置的地面场景首次进入时，以当时玩家位置寻找两处安全落点；失败每10秒重试，不生成半套站点。默认间距至少6米。 |
| 子场景识别 | 地下子场景不会仅因其父地图属于目标地图就生成新站点；农场镇南部有独立目标键。已保存的站点与车辆仍可恢复。 |
| 旧版兼容 | 保留0.1.0存档键、原有站点ID及坐标；新增场景单独建站。修改配置不会搬动原有站点。 |
| 场景切换 | 子场景卸载前记录停车位置、解除骑行、清除未完成的上下车/还车状态；子场景加载期间不计费、不创建站点。 |
| 视觉跟随 | 自行车跟随改到LateUpdate，减少角色与车辆因更新顺序产生的位置滞后；仍使用占位车模。 |
| 保存失败 | 临时写入失败保留当前租赁、车辆与订单，等待场景/角色可保存时每5秒重试，不因临时保存失败永久停用租还功能。读入损坏资料仍停止业务，并保留原数据。 |
| 保存提示 | 尚未确认保存时显示提示。成功写入并读回后消失；连续相同错误不重复刷日志。 |
| 付款会话 | 保存及现金网关绑定当前租赁引擎与存档槽。回调导致切换存档时拒绝向另一槽位写入旧付款回执。 |
| 付款快照 | 保存前后核对实际业务资料与PaymentService请求的快照；收集资料失败不能继续当作付款检查点成功。 |
| 现金落盘核对 | 付款时读回背包、可用仓库、宠物安全库存的原生保存数据，核对现金物品451的实例ID及数量，补充业务/世界/回执文件校验。 |
| 原生保存开关 | 付款要求人物与涉及的安全库存可以保存；仓库加载中不扣款。普通地图记录尊重原游戏SaveCharacter开关，不强行改变原生存档规则。 |
| 资料校验 | 拒绝重复站点ID、错误槽位/世界版本、无效坐标/车辆来源、重复或错误付款回执、不符合记录余额变化的回执。 |

## 原型范围

三个地图已经有站点接入代码和默认配置，**尚未在运行中的游戏里确认各场景生成成功**。站点仍以首次进入位置为锚点，不能视为已完成正式站点布局或地图平衡。正式站点需要日后核实入口、搜刮区、撤离路线及安全地面，才能确定固定坐标。

未归还车辆仍暂时禁止切换主地图；下车后可使用当前主地图内的普通子场景通道，车留在原场景。这是0.1.0原型的临时限制，尚未实现设计中的完整跨主地图停车恢复。

鸭子仍沿用原移动姿态，专用坐姿、踩踏动画及车体尺寸碰撞未完成。账单仍在马蜂原窗口旁展示，未合并为原物品包裹条目。主动报失2000元沿用设计默认值，与用户已确认的死亡赔偿分开。

保存重试仅能在本次游戏进程仍保有租赁与现金回执时重试。如果提示未消失就退出、进程崩溃或磁盘持续故障，不能保证最新状态恢复。扣款回调中切换存档、其他模组绕过SavesSystem直接写文件、原生临时文件/备份恢复仍需实际故障验证；不能把离线模拟当作崩溃一致性证明。

## 配置

配置位置：模组目录`prototype.json`。默认值：

```json
{
  "Enabled": true,
  "AutomaticTestStations": true,
  "TargetDisplayKeys": ["Level_GroundZero", "HiddenWarehouse", "Level_Farm", "Level_Farm_South"],
  "StationsPerScene": 2,
  "MinimumStationSeparation": 6,
  "PlacementRetrySeconds": 10,
  "FixedStations": []
}
```

每场景站点数量允许2～4，间距允许4～30米，重试间隔允许2～120秒。目标列表替换默认列表，避免JSON反序列化把列表重复追加。设置`Enabled=false`关闭新租赁及自动布点，已有站点、车辆和账单保留以便归还与结算。

固定站点需提供唯一Id、Name、实际MapId、实际SceneName、Position的X/Y/Z。此版不提供未核实的固定坐标，不会随更新静默移动旧站点。
