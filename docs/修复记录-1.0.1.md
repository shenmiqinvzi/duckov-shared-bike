# 1.0.1 修复记录：站点看不见、上车不能动、账单支付

日期：2026-10-21。基线：1.0.0（2026-10-14 安装）。本机游戏目录 `E:\Steam\steamapps\common\Escape from Duckov`。

本轮针对试玩反馈的三个问题做了定点修复。修复来自代码与已安装日志/存档的核对，输出仍是**待游戏内复验**，不把编译通过写作实景验收。

## 一、看不到自行车和站点模型

### 已确认的证据

安装目录 `logs/bootstrap.log` 从 10-14 到 10-19 共记录 12 次：

```text
NullReferenceException
  at InteractableBase.Awake () [0x00079]
  at DuckovSharedBike.SharedBikeInteractable.Awake ()
  at DuckovSharedBike.BikeWorldController:AddInteraction(...)
```

反编译 `TeamSoda.Duckov.Core.dll` 的 `InteractableBase.Awake`，在偏移 `0x79` 处执行的是：

```text
IL_0079: ldfld InteractableBase::otherInterablesInGroup   // 序列化字段，运行时创建时为 null
IL_007f: callvirt List`1<InteractableBase>::GetEnumerator // 空引用
```

原实现把交互组件直接加在站点/自行车的根物体上，`Awake` 在初始化前就抛异常；同时原生 `Awake` 会把**碰撞体所在物体**的层改成 `Interactable`（本机第 8 层，不是渲染层）。第 8 层只会改到根物体，子物体上的几何体原本仍在 Default 层，所以**层本身不足以解释“完全看不见”**；更可能的原因是材质：原实现只靠 `Shader.Find("Universal Render Pipeline/Lit")` 建材质，构建版里若该 shader 不在可查找列表，`_frame/_dark/_metal/_sign` 会全部为 null，而运行时 `CreatePrimitive` 的默认材质也可能被剥离，Renderer 就没有可画的材质。这两条 1.0.1 都做了兜底，见下。

### 修复

- `SharedBikeInteractable.Awake` 先用反射给 `otherInterablesInGroup` 与 `_interactbleList` 填入空列表，再调用 `base.Awake()`；`base.Awake()` 仍然失败时也不再中断后续设置。
- 交互触发器改挂到站点/车体根下的独立子物体 `InteractPoint`，只有这个子物体进入 `Interactable` 层，模型留在可见层。
- 模型材质改为**克隆游戏自己正在渲染的材质**（优先玩家角色材质），不再依赖 `Shader.Find("Universal Render Pipeline/Lit")`；找不到模板时才回退到 URP Lit/Unlit/Standard/Unlit 链。
- 创建时按 `Camera.main.cullingMask` 选择可见层，并写日志：`Visuals use game material template ...`、`Bike visual created layer=... renderers=...`。
- 站点模型加高到 2.15 米并加了低位小牌；站点名和距离改成从**存档站点坐标**直接画屏幕标签（60 米内），即使三维模型仍异常也能找到位置。
- 地图标记不再把 POI 挂回子场景根（原生 `Create` 会把它放进主场景），并在 `preview.png` 读取失败时生成一个绿色圆环图标兜底。

## 二、上车后不能移动

### 已确认的证据

反编译确认：

```text
CA_Interact.CanMove() => false
CharacterMainControl.CanMove() => currentAction == null || currentAction.CanMove()
```

原 `Awake` 空引用导致 `finishWhenTimeOut=true`、`interactTime=0.2` 这两行**没有执行**。交互动作因此不会到时完成；一旦按下交互键，`CA_Interact` 一直保持 running，`CanMove()` 恒为 false，角色原地卡住。存档里两次租赁分别只持续 19.5 秒和 38.3 秒，且都在原地归还；两次租赁期间都出现过 `Native rider pose ready`（10-14 一次、10-15 三次），和“骑上就动不了、马上还车”一致。

另外，旧 `LateTick` 在车体空间检查失败时会 **`actor.SetPosition(上一个点)`**，每帧把玩家拽回原位，也会表现为完全不能走。

### 修复

- 交互组件初始化恢复后，交互 0.2 秒自动完成并停止动作。
- 骑行时**拦截所有动作**（原实现给“目标为共享单车交互物”的交互动作留了口子，动作可以在骑行中重新启动并锁死移动）。
- 骑行中每帧检查 `CurrentAction`：只要它 `CanMove()==false` 就停止并记日志（`Ride guard clearing native action ...`）。
- 上车时显式 `movementControl.MovementEnabled = true`，并记录 `Mounted speed=... moveability=... action=...`。
- 车体空间检查降级为**提示**：不再回写玩家位置；失败只提示一次，自行车继续跟随玩家。`VehicleClearance` 仍保留为配置项，便于以后重新启用硬碰撞。
- 若仍出现不能移动，日志会写入 `Ride guard: CanMove=false speed=... movementEnabled=...`，可据此区分“动作锁死”和“移速为 0”。

## 三、自提点账单要分两步支付

### 现状核对

存档 `Save_1.sav` 中两笔订单都是 `PaymentStatus=Paid`，各有一条 `PaymentOperationId` 和一条现金回执（6807→6607、36979→36779），没有 `Pending` 残留。说明**模组自己的按钮是一次点击完成扣款的**，不存在“点提取后再点支付”的第二道确认。

模组面板只有一个按钮。旧文案是“提取并支付 200元”，恢复付款时是“提取（恢复付款）”。玩家看到的“提取”很可能是**原游戏自提点自己的物品提取按钮**（`StorageDock.OnTakeBufferItem`），它只处理寄存物品，与单车账单无关；随后仍需在右侧模组面板点一次单车账单。

### 本次调整

- 按钮文案统一为“**提取账单并支付 N元**”，并在现金行注明“点击账单即扣款”，不再出现“提取”和“支付”两个动作的歧义。
- 付款结果写入日志：`Payment order=... code=... pending=...`。
- 付款异常（`PaymentBusy`）改为明确提示“保持自提点窗口打开再点一次；同一账单不会重复扣款”。

如果要的是“按原游戏提取键就自动把单车账单也扣掉”，需要额外补丁 `StorageDock.OnTakeBufferItem`；这会在取普通寄存物时也触发扣款，默认没有这样做，待确认后再加。

## 复验顺序

1. 完全重启游戏，确认 F9 面板显示 `v1.0.1`。
2. 进入零号区，找绿色地图标记或屏幕上的站点名字标签，确认能看到站点的杆和黄色牌。
3. F6 租车，确认自行车出现在身边 1.6 米内且可见；F7 上车，直接按 W 移动，记录是否能走。
4. 若不能走，按 F10 后提供日志末尾；应能看到 `Mounted speed=` 或 `Ride guard:` 行。
5. 还车、撤离、打开马蜂自提点，只点一次“提取账单并支付 200元”，确认现金只扣一次、订单进入“已付款历史”。
