## 已完成的业务代码

- 一个存档最多一辆待归还车辆；停车仍属租赁中，不能租第二辆。
- 租车创建失败不留账，不产生最低租赁费。
- 按未暂停的实际游玩时长收费；保存小于1毫秒的时间余量，避免逐帧截断累计误差。
- 每小时200元，不足一小时按一小时计；租赁成功后立刻归还也收200元。
- 正常归还停止计费；欠费限制再次租车，允许撤离。
- 死亡额外赔偿2000元，重复死亡/归还通知只生成一份结算单。
- 主动报失暂按额外2000元处理；这是设计默认值，尚未作为新金额单独确认。
- 系统故障回收不追加赔偿。
- 业务层骑行行为矩阵：禁止战斗、冲刺、消耗品和指定世界交互，保留地图/背包查看及下车/归还。
- 存档恢复保留租赁、合同价格、累计时长和欠费，默认恢复为停车姿态。
- 订单金额冻结，余额不足不部分扣款；全部欠费付清才允许再租。
- 付款准备、结果确认、重复请求和失败恢复协议；可识别未知扣款结果并保留待恢复状态。
- 保存数据的完整性校验，拒绝重复租赁、错存档、未知版本、订单金额不一致等数据。

### 验证范围

自动化测试不启动游戏，使用同一份业务源代码，以及游戏自带Newtonsoft.Json进行序列化兼容验证。付款失败测试使用模拟的持久、幂等现金网关，并注入扣款后异常、账单提交失败、余额不足和错误回执。

这证明业务协议可按要求处理这些情况，**不证明原游戏现金扣款已经具备同样的幂等能力**。真实付款接入需单独解决：现金消耗、现金回执与账单一起持久化、游戏文件提交失败及存档回滚。

游戏 `SavesSystem.Save()` 写入缓存，`SaveFile()`才提交到文件；二者不能混同。当前缓存适配器不实现付款服务所要求的持久事务接口，因此尚未开放真实扣款。

暂停/加载边界采用保守采样：仅两个连续活跃样本之间累计时间，恢复第一帧不把暂停期间的时间补记。实际暂停判定、帧边界误差与场景流程仍需游戏内验证。
