# 1.0.11 记录：共享单车黑化涂装

日期：2026-11-02
基线：1.0.10（召车 3 秒 + 音效修复）

## 1. 需求与边界

需求（用户原话要点）：轻度恶灵骑士/地狱火废土风，不改摩托、不堆夸张装甲，保留车架/轮组/车把/座椅与"共享单车"识别点（编号牌/车筐/后架）；车架是黑/深灰磨损金属带刮痕锈蚀；火焰只做点缀（轮圈/前叉/尾部微弱橙红）；可以有车头机械骷髅徽记；主色黑/深灰/锈银，点缀暗红/橙红/少量幽蓝。

落地时的三条硬约束：

- **没有外部资源管线**。Build.ps1 的打包白名单只有 10 个文件，没有 AssetBundle/模型/贴图导入流程，所以一切只能是"程序化几何 + 运行时 `Texture2D` + 克隆游戏已有 shader"。概念图里那种真实火焰包裹、写实骷髅做不到，做出来是"几何骨架 + 自发光"，这是设计取向而不是临时妥协。
- **材质原本是共享的**。`_frame/_dark/_metal/_sign/_glow/_glowRed` 同时被 `Station()` 使用，直接把车身调黑会让九个站点一起变黑。所以先给自行车单开一套材质，站点配色一个字节都没动。
- **车架拓扑不能动**。`RiderSeat`(0, 0.60, -0.11)、`Grip.Left`(-0.19, 0.94, 0.22)、`Grip.Right`(0.19, 0.94, 0.22) 三个锚点与 `BicycleGeometry`（`WheelRadius=0.26`、`HalfWheelbase=0.42`）被坐姿、踩踏与净空检查引用，改坐标就是回归。这次只换材质与增加表面件，坐标全部原样。

## 2. 材质分层

`src/DuckovSharedBike/PrototypeAssets.cs:87` 新增 `CreateBikeMaterials(template, shader)`，用同一套模板/shader 克隆出七个车身专用材质：

| 字段 | 用途 | 颜色 / 参数 |
| --- | --- | --- |
| `_bikeFrame` | 车架、挡泥板 | 磨损贴图 + `_Metallic 0.8`、`_Smoothness 0.22` |
| `_bikeDark` | 座垫、把套、踏板 | (0.045, 0.048, 0.055)，`_Smoothness 0.2` |
| `_bikeMetal` | 辐条、轮毂、车筐、灯座、徽记底板 | (0.45, 0.46, 0.49)，`_Metallic 0.9` |
| `_bikeEmber` | 前灯、骷髅眼窝 | (1, 0.4, 0.12)，Emission ×2.1 |
| `_bikeEmberDim` | 24 段轮圈、余烬条纹、旗面 | (0.72, 0.18, 0.05)，Emission ×1 |
| `_bikeCold` | 尾灯、后反光片 | (0.28, 0.62, 1)，Emission ×1.3 |
| `_bikePlate` | 编号牌照 | 车牌贴图 + `_Metallic 0.25` |

顺手统一了原来的两套分支：`EnsureMaterials()`（`src/DuckovSharedBike/PrototypeAssets.cs:54`）现在只判断一次 `template/shader`，用 `Create()` 走 `Tint()` 或 `MakeMaterial()`；旧的无调用 `Glow()`/`MakeGlow()` 删除，改由 `Emissive(material, intensity)` 统一加自发光。

两个容易踩的坑：

- **贴图会把基色乘黑**。URP Lit 的最终颜色是 `_BaseColor × _BaseMap`，贴图基色只有 0.115，再乘 0.14 就是纯黑。所以 `ApplyTexture()` 在成功挂上贴图后把 `_BaseColor` 置白，让贴图自己决定明暗。
- **`_EMISSION` 需要显式开启**。`Emissive()` 里 `EnableKeyword("_EMISSION")` 之后才写 `_EmissionColor`，否则 URP 不编译 emission 分支；顺手用 `HasProperty` 兜底，模板 shader 没有该属性时退化成纯色，不会抛异常。

## 3. 程序化贴图

`BuildWornMetalTexture()`（`src/DuckovSharedBike/PrototypeAssets.cs:320`）：192×192，值噪声（`Hash01`/`ValueNoise`/`Fbm`，4 个八度）打底，`blot>0.58` 混入锈色 (0.31, 0.13, 0.055)，`blot<0.34` 混入冷钢色提亮，再画 16 条随机划痕。随机源固定 `new System.Random(7)`，每次生成的纹理完全一致，便于对比截图。划痕方向被约束在 v 轴附近（`Math.PI*0.5 ± 0.45`），因为圆柱 UV 的 v 方向是管长，顺着它才像金属刮擦，横着画会变成噪点。划痕用 2×2 像素块，单像素在 14 cm 周长的管子上只有 0.7 mm，远看等于没有。

`BuildPlateTexture()`（`src/DuckovSharedBike/PrototypeAssets.cs:374`）：160×64，5×7 点阵字形表 `Glyphs`（0–9、A、-），文本 `A-0427`，缩放 3，四周一圈暗金边框。`PaintText()` 按左下角原点写入，所以行序做了 `6 - row` 翻转。

两张纹理都在 `Apply(..., true)` 时释放 CPU 副本，`Dispose()`（`src/DuckovSharedBike/PrototypeAssets.cs:584`）里连同七个材质一起销毁，不会随场景切换泄漏。

## 4. 几何改动

`Bike()`（`src/DuckovSharedBike/PrototypeAssets.cs:184`）只换材质并追加表面件：

- 轮圈 24 段全部换成 `_bikeEmberDim`，转起来是两圈暗红余烬；辐条与轮毂仍是冷金属，形成"烧红铁圈 + 冷钢辐条"的对比。
- 车架三角、后叉、座管、立管仍用原来的坐标，只是材质换成 `_bikeFrame`；车筐从绿色改成金属网筐，形状不变（共享单车最强识别点）。
- 后反光片从黄色改成 `_bikeCold` 幽蓝。
- `Decorate()`（`src/DuckovSharedBike/PrototypeAssets.cs:252`）：挡泥板弧换 `_bikeFrame`；前灯是烧红的球；尾灯改幽蓝；旗面改暗红余烬；车架余烬条纹从 4 条减到 2 条，避免整辆车变霓虹灯。
- `Emblem()`（`src/DuckovSharedBike/PrototypeAssets.cs:278`）车头机械骷髅：一块 0.26×0.17 的暗银挡板 + 两个发光眼窝 + 鼻腔 + 4 颗齿 + 3 段头顶弧，共 11 个 renderer。位置压在车筐前壁 (z≈0.55)，不挡车把。
- `Plate()`（`src/DuckovSharedBike/PrototypeAssets.cs:297`）：一根短支架从挡泥板尾部垂下，末端挂 0.22×0.09 的牌照，位置 (0, 0.42, -0.63)，在后轮后方，不与轮圈相交。
- `CreateEmberLight()`（`src/DuckovSharedBike/PrototypeAssets.cs:305`）：**只加一盏**点光（(0, 0.34, -0.4)，range 2.3，intensity 0.85，`LightShadows.None`）。URP 的附加光有数量上限，多一盏就可能把场景自己的灯挤掉，所以宁可少。

renderer 总数从约 105 增到约 117，仍在 +30 的预算内。

## 5. 余烬呼吸

`BicycleVisual.ConfigureFire(ember, emberDim, light, color)`（`src/DuckovSharedBike/BicycleVisual.cs:29`）接收两个材质与一盏灯，`Update()`（`src/DuckovSharedBike/BicycleVisual.cs:39`）用 `Time.unscaledTime` 算 `pump = 0.78 + 0.16·sin(2.7t) + 0.06·sin(6.9t + 0.7)`：

- `_bikeEmber` 的 `_EmissionColor` 设为 `color × (1.6 + pump × 1.1)`，落在 HDR 区间，能吃到 bloom；
- `_bikeEmberDim` 设为 `(0.72, 0.18, 0.05) × (1.5 + pump × 0.9)`，轮圈亮但不刺眼；
- 点光强度 `0.45 + pump × 0.5`，跟随呼吸轻微起伏。

两条正弦频率不成整数比，所以看不出循环节。用 `unscaledTime` 是为了暂停菜单里火焰还在烧——这是刻意的，暂停时车灯熄灭反而像 bug。`Update()` 里只有浮点运算与 `SetColor`，没有分配。

## 7. 待游戏内复验

1. 10 米外还能不能一眼认出是"共享单车"——车筐、车轮轮廓、牌照是三个关键识别点。
2. 站点是否仍是绿底黄边（如果站点变黑，说明有材质被误改回共享引用）。
3. 上车后坐姿、脚部踩踏、坡地姿态是否与 1.0.10 一致（材质改动不应影响，但锚点必须眼见为实）。
4. 夜间轮圈余烬是否过曝；若太亮，把 `BicycleVisual.Update()` 里 `_bikeEmberDim` 的乘数从 `1.5 + pump × 0.9` 往下调。
5. 车牌在 0.22×0.09 的尺寸下 "A-0427" 是否可读；不可读就把 `PaintText` 的 `scale` 从 3 调到 4。
