# 1.0.2 改进记录：启动自检、存档降频与可配置项

日期：2026-10-21。基线：1.0.1。目标：在不改变核心玩法的前提下，降低“游戏更新后带病加载”和“存档过重”的风险，并把试玩反馈里靠猜的部分变成可配置项。仍未启动游戏，改进只做到编译、测试和安装校验。

## 1. 启动原生契约自检

新增 `src/DuckovSharedBike/NativeContract.cs`。模组启用时先检查本模组依赖的约 50 个原生成员，全部通过才继续加载：

- Harmony 补丁目标：`CharacterMainControl` 的移动/动作/交互方法、`Movement`、`Stat.Value`、`Item.CanDrop`、`ItemAgent_Gun`、`CountDownArea`、`MultiSceneTeleporter`、`SceneLoader`、`SceneLoaderProxy`、`LevelManager`、`SavesSystem`、`ES3Internal.ES3IO` 等。
- 反射字段：`InteractableBase.otherInterablesInGroup`、`_interactbleList`、`interactTime`、`finishWhenTimeOut`、`interactMarkerOffset`。
- 运行时接口：`StorageDock.Instance/open`、`View.ActiveView`、`EconomyManager.Cash/Pay`、`SimplePointOfInterest.Create`、`CharacterModel.LateUpdate`、`CharacterModelAudioPoster.PostFootStepSound`。

结果写入日志一行：

```text
Native contract ok checked=...
```

或：

```text
Native contract FAILED checked=... missing=CharacterMainControl.CanMove, ...
Mod did not start: native contract failed. The game build is not the one this mod was verified against.
```

不匹配时**不加载业务系统**，F9 面板直接显示“原生契约：缺少 N 项…”，避免出现“部分补丁生效、部分没生效”的难查状态。检查本身如果抛异常也会被捕获并提示，不会把异常抛回游戏加载器。

### 离线核对

新增只读脚本 `tools/AssetInspector/check_contract.ps1`，用反射直接对照本机 `Duckov_Data\Managed` 里的程序集，逐项检查上述成员。当前结果：除 `SimplePointOfInterest` 因 .NET Framework 无法加载该类型（游戏 Mono 下正常，且模组编译期已解析）外，其余成员全部找到。这个脚本不进入安装包。

## 2. 周期完整存档从 5 秒放宽到 20 秒

`NativeRentalRuntime` 每 5 秒做一次完整原生保存：`SaveMainCharacter → CollectSaveData → SaveFile → 原子替换 → 回读整个文件校验`，还包含备份。租赁期间持续执行，代价偏高。

改为：

- 默认每 **20 秒**一次，可在 `mod/prototype.json` 的 `Persistence.FullSaveSeconds` 调整（允许 5–300）。
- 保存失败后的重试仍是 **5 秒**，不会因为降频让失败状态拖太久。
- 上车、还车、付款、死亡、会话退出这些关键节点仍然**立即**保存，不受周期影响。

```json
"Persistence": { "FullSaveSeconds": 20 }
```

## 3. 按键与面板可配置

```json
"Keys": {
  "Station": "F6",
  "Mount": "F7",
  "Loss": "F8",
  "Diagnostics": "F9",
  "Snapshot": "F10"
},
"Ui": {
  "InvoicePanelSide": "right",
  "ShowWorldLabels": true
}
```

- 按键用 Unity `Key` 枚举名（如 `E`、`Q`、`F7`、`LeftShift`）。解析失败会写日志并回退默认值，不会让模组起不来。
- `InvoicePanelSide` 可选 `right`/`left`。右侧会压住部分原游戏侧栏，左侧适合把账单面板挪开；`ShowWorldLabels` 控制屏幕上的站点名/距离标签。
- HUD 提示和 F9 面板会跟随配置显示实际按键，不再写死 F6–F10。

## 4. 其他细节

- `BikeWorldUI` 的 `GUIStyle` 改为首次绘制时缓存，不再每帧 `new GUIStyle`。
- 自行车地图标记每秒跟随车体位置，归还时随车辆一起销毁（避免地图上留下旧标记）。
- 新增日志：`Rent started ...`、`Return closed order=... total=...`、`Recovery reason=...`、`Periodic full save interval=...`、`Map markers active ...`。
- F9 面板增加：原生契约状态、模型层/部件数、存档频率、当前按键。

## 5. 验证

- 自动测试 **160/160** 通过（新增 5 项运行配置校验：默认值、显式覆盖、非法存档间隔/面板方向、空或重复按键、大小写重复）。
- 目标游戏程序集编译 0 警告、0 错误。
- 1.0.2 安装包 10 个文件 SHA256 校验通过。
- **未启动游戏**。原生契约检查的成员来自本机程序集反射；实际运行时 Mono 的加载行为、按键解析和面板位置仍需进游戏确认。

## 6. 出问题怎么查

F9 面板先看“原生契约”。如果显示缺少项，说明游戏版本/其他模组改动了原生接口，日志里有完整列表；把 `logs/bootstrap.log` 末尾和缺失行发回即可。若契约通过但进图仍异常，日志里的 `Bike visual created`、`Station visual created`、`Mounted speed`、`Ride guard`、`Rent started`、`Return closed` 会把流程卡点标出来。
