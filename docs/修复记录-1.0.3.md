# 1.0.3 修复记录：还车后找不到返回通道

日期：2026-10-21。基线：1.0.2。反馈：从地堡地道进入零号区，骑了一段自行车并在 `gz-east` 归还，之后原路返回的隧道/井盖没有交互点，无法回地堡。

## 已核对的事实

- 存档 `Save_1.sav`：本次租赁 `Status=1`（已关闭）、`ReturnStationId=gz-east`、`Vehicle=null`，订单 200 元未支付；**没有欠车**，不是“未还车禁止撤离”触发的。
- 日志：`Return closed order=... station=gz-east`，随后到退出前没有场景切换；租赁关闭正常。
- `Duckov.Scenes.MultiSceneTeleporter` 和 `SimpleTeleporter` 都继承 `InteractableBase`；`MultiSceneTeleporter.OnInteractFinished` 里是 `DoTeleport()` + `StopInteract()`。旧实现把拦截放在 `DoTeleport` 前缀里——交互已经完成、`StopInteract` 已经执行后才被拒绝，如果该传送点配置了 `disableOnFinish`，它会被当成一次已完成交互而关闭。
- 站点交互物与原生传送点都在 `Interactable` 层；游戏交互扫描通常只保留一个最近目标。站点若落在传送点附近，可能把“返回通道”的提示顶掉，玩家看到的就是“没有交互点”。

这两条都能解释“还车后回不去”，且都是模组侧可修的。

## 修复

1. **站点交互让位**：每 2 秒扫描当前场景的 `MultiSceneTeleporter` / `SimpleTeleporter`，缓存位置与碰撞体。玩家在原生传送点 3.5 米内时，`CanMountInteract` / `CanUseStation` 返回 false，共享单车的提示隐藏，让原生“返回通道”提示出现。会写日志：
   ```text
   Shared-bike prompt suppressed near native travel point ...
   ```
2. **拦截提前到交互开始**：新增 `InteractableBase.StartInteract` 前缀。欠车时若目标是 `MultiSceneTeleporter`，先走 `AllowTeleport` 判断；不允许就 `__result=false` 直接拒绝，交互不会完成，因此不会触发 `OnInteractFinished` / `StopInteract` / `disableOnFinish`。日志：
   ```text
   Teleport blocked source=start target=... debt=True riding=...
   ```
   原有的 `DoTeleport` 前缀保留为触发式传送的兜底，也会记 `source=do`。
3. **返回通道屏幕标签**：`DrawWorldLabels` 新增最近两个原生传送点的“返回通道 N米”标签（80 米内），不依赖地图标记，也不依赖站点模型是否可见。
4. **F9 脱困按钮**：F9 面板底部新增“脱困：重新启用附近通道”。点击后重新启用玩家 30 米内被禁用的传送点组件与交互碰撞体，并写日志：
   ```text
   Travel point repair repaired=N nearby=M
   ```
   这是卡住时的最后手段，可能重新打开一次性通道，已标注“仅用于卡住时”。
5. **传送点诊断**：进入地图后逐个记录：
   ```text
   Native travel point <name> type=... pos=... enabled=... collider=... disableOnFinish=...
   ```
   下次若仍异常，这行能区分“传送点被禁用”“碰撞体关闭”“位置不对”还是“提示被顶掉”。

## 已经卡住的存档怎么办

1. 进游戏后按 F9，点“脱困：重新启用附近通道”，再走回隧道/井盖附近查看提示。
2. 如果按钮提示“附近没有可修复的通道”，说明传送点不是被禁用，而是位置/触发问题；可以退出到主菜单重新读档，或重新进入零号区，让传送点按原生流程重新生成。
3. 反馈时请附日志末尾，重点找 `Native travel point`、`Shared-bike prompt suppressed`、`Teleport blocked`、`Travel point repair`。
