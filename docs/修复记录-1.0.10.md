## 2. 提示音完全静默

### 证据

`%USERPROFILE%\AppData\LocalLow\TeamSoda\Duckov\Player.log` 在 11-01 那一局的三个时间点各出现一条：

```
AudioClip.SetData failed; AudioClip  contains no data
```

三条的位置精确对应三次播放调用（玩家日志行号为 5803/5837/5989）：

- 5803 紧挨 `[DuckovSharedBike] Summon started ...`：`Summon()` 在写日志前调用 `_sounds.SummonTone()`（`src/DuckovSharedBike/BikeWorldController.cs:586`）。
- 5837 在 `Bike visual created` 之后、`Summon completed ...` 之前：`CompleteSummon()` 里的送达音 `_sounds.RentTone()`（`src/DuckovSharedBike/BikeWorldController.cs:627`）。
- 5989 紧跟 `Settle order=... code=Success`：`SettleOrder()` 的扣款成功叮（`src/DuckovSharedBike/BikeWorldController.cs:923`）。

### 根因

`BikeSounds` 用 `AudioClip.Create(name, samples, 1, 44100, false)` 生成静态 clip，再 `SetData` 写入采样。该环境里创建出来的 clip 没有可写缓冲：

- `AudioClip.SetData` 返回 `false` 并在 Player.log 报 `contains no data`，**不抛异常**；
- 模组自己的日志因此一片正常（`Play` 的 catch 永远不会命中），`PlayOneShot` 照样调用，只是播的是空 clip；
- 错误信息里 clip 名为空（`AudioClip  contains no data` 中间两个空格），说明这个 clip 连名称都没有落到运行时对象上。

### 修复

`src/DuckovSharedBike/BikeSounds.cs` 改为三级策略，每级都有日志：

1. 仍先试静态 clip + `SetData`，但检查返回值；失败一次即记 `sound: AudioClip.SetData unavailable; using streaming PCM clips.` 并永久切到第 2 级。
2. 流式 PCM 回调 clip：`AudioClip.Create(name, samples, 1, Rate, true, buffer => ...)`，数据由回调直接供给，不依赖静态缓冲。
3. 若拿到的 clip 长度为 0，则借用游戏已加载的短提示音（`Resources.FindObjectsOfTypeAll<AudioClip>()`，优先名称含 ui/click/notif/beep/chime/confirm、长度 0.08–0.5 秒者），并用 `pitch=1.4` 播一个近似的“叮”；找到时记录 `sound: borrowed game clip '...'`。

附带修正：

- `AudioSource` 设置 `ignoreListenerPause = true` 与 `bypassEffects/bypassListenerEffects/bypassReverbZones = true`，避免开背包或暂停时提示音被 AudioListener 一起暂停。
- `Ui.Sounds=false` 以前只遮住了 2 个调用点（自动结算），召车/送达/余额不足仍然会响；现在由 `BikeSounds.Enabled` 统一控制（`src/DuckovSharedBike/BikeWorldController.cs:103`）。
- 同一段铃声不再每次播放都重新合成（原实现每次 `Build` 新 clip 并覆盖字典引用，旧 clip 永不销毁）。
- 零长度 clip 与播放异常各只记一次日志，避免刷屏。
- 启动时记录 `sounds enabled=... outputSampleRate=...`（`src/DuckovSharedBike/BikeWorldController.cs:104`），下次排查能直接看到音频子系统状态。
