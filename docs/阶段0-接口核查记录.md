## 2. 已核实的接口

### 模组生命周期与安装结构

`Duckov.Modding.ModBehaviour` 提供 `OnAfterSetup()` 与 `OnBeforeDeactivate()` 两个受保护虚方法。

本机IL确认：`Setup()` 设置 `master`、`info` 后调用 `OnAfterSetup()`；`NotifyBeforeDeactivate()` 调用 `OnBeforeDeactivate()`。加载测试版直接覆写这两个接口，卸载时退订场景事件并释放自己创建的字体。

`ModManager.DefaultModFolderPath` 为 `Application.dataPath/Mods`。`TryProcessModFolder()` 读取 `info.ini` 的name、displayName、description、version、tags，查找对应DLL和preview.png；`ActivateMod()`加载DLL并查找 `<name>.ModBehaviour`。

本模组使用 `name=DuckovSharedBike`、`DuckovSharedBike.dll`、`DuckovSharedBike.ModBehaviour`，导出类型的基类与本机加载器要求一致。

### 当前玩家与场景

`CharacterMainControl.Main` 是公共静态属性。本机IL显示它通过 `LevelManager.Instance.MainCharacter` 获取玩家，并处理LevelManager不存在的情况。加载测试版只读取玩家Transform位置。

`LevelManager` 提供 `IsBaseLevel`、`IsRaidMap`、`LevelInitializing`、`LevelInited` 及初始化事件。诊断阶段通过Unity `SceneManager`记录活动场景、全部加载场景和玩家所属场景。

### 移动与负重

候选接入点包括 `CharacterMainControl.CharacterWalkSpeed`、`CharacterOriginWalkSpeed`、`CanMove()`，以及 `Movement.UpdateMovement()`、`UpdateNormalMove()`。

`CharacterMainControl.UpdateWeightState()` 根据角色物品总重量、最大负重及搬运状态计算重量状态，并通过 `GameplayDataSettings.Buffs` 添加轻负重、重负重、超重等Buff。

**结论：负重减速不是已经确认的单一系数。** 后续需继续追踪Buff对步行速度和移动锁定的具体影响，仅在骑行期间补偿速度，不直接删除负重Buff的全部效果，也不修改物品重量。本轮未实现速度补偿。

### 死亡与撤离

`LevelManager.OnMainCharacterDead` 是公开订阅事件，参数为 `DamageInfo`；另有 `OnEvacuated` 和 `EvacuationInfo`。场景相关类包括 `SceneLoader`、`SceneLoadingContext`、`ExitCreator` 和 `EvacuationCountdownUI`。

死亡事件可以作为后续回收候选入口；**撤离完成通知不能替代撤离开始前的拦截**。本轮尚未定位并验证全部正常撤离触发与完成路径，死亡回地堡必须与普通撤离区分。

### 现金与账户余额

`Duckov.Economy.EconomyManager` 明确区分 `Money`（账户余额）和 `Cash`（现金物品数量）。现金物品TypeID为451，`Cash`通过 `ItemUtilities.GetItemCount(451)`查询。

公共方法签名包括：

```text
EconomyManager.Pay(Cost cost, bool accountAvaliable, bool cashAvaliale)
EconomyManager.IsEnough(Cost cost, bool accountAvaliable, bool cashAvaliale)
Cost.Pay(bool accountAvaliable, bool cashAvaliable)
```

参数拼写按本机程序集原样记录。读取方法IL可见，可分别允许/禁止账户余额和现金参与扣款。

**施工约束：用户要求扣现金，候选方案为禁用账户余额、启用现金，即两个开关使用false/true。** 现金涵盖的具体容器、消费顺序、交易失败行为及存档一致性仍需继续核查和游戏内验证，不能把Money与Cash合并后称作现金。

### 物品与交互

存在 `CA_UseItem`、`CharacterActionBase`、`CharacterInputControl`、`InteractableBase` 和 `MultiInteraction` 等类。后续需在实际执行入口实施食药和战斗限制，不能仅屏蔽按键。

游戏有 `InteractableVehicle` 和 `CharacterAnimationControl_Moto`，但当前不能由类名推断其能直接复用为共享单车。`InteractableVehicle`关联另一CharacterMainControl与限时控制字段，复用之前需要核实角色控制、速度、伤势和卸载行为。

### 马蜂自提点

发现 `PlayerStorageBuffer`，含 `incomingItemBuffer`、`Buffer`、`SaveBuffer()`、`LoadBuffer()`，可能与待领取物品有关，需要在地堡场景确认实际关联。

`Duckov.UI.ItemPicker` 经方法签名核查是从候选物品集合中选择物品的UI，**不能直接认定为马蜂自提点**。

本轮尚未验证马蜂现场对象、UI提取入口和订单载体。下一阶段需要定位现场对象或其引用链，确定付费结算接入和背包已满时的处理方式。

### 存档

`Saves.SavesSystem` 提供 `OnSetFile`、`OnCollectSaveData`、`Save()`、`SaveFile()` 等接口。尚未核查数据写入时机与现金物品保存机制，不能据此宣称扣款和模组订单天然原子保存。

## 7. 0.2.0三地图与保存检查

本机CSV确认目标显示名键`Level_GroundZero`、`HiddenWarehouse`、`Level_Farm`及区域名`Level_Farm_South`；元数据和IL确认SceneInfoEntry.DisplayNameRaw、MultiSceneCore.DisplaynameRaw及主/子场景相关接口。新代码按当前场景定位测试站点，不用父地图名称误匹配地下子场景。子场景加载期间停计时，卸载前记录停车资料。旧站点和车辆数据使用原存档键，新增世界资料校验。1.0.0追加实际场景资源核查确认，Farm_South不是独立的第四个场景。

IL进一步确认EconomyManager.Cash通过ItemUtilities.GetItemCount(451)汇总人物库存、可用PlayerStorage和PetProxy库存。ItemSavesUtilities的前缀保存经SavesSystem.Save(prefix,key,value)拼接真实键；人物为`Item/MainCharacterItemData`，仓库为`Inventory/PlayerStorage`，PetProxy为`Inventory/Inventory_Safe`。人物和安全库存分别受LevelConfig.SaveCharacter/SavePet控制，仓库加载时跳过保存。付款接入据此增加可保存条件检查及各现金库存的文件读回核对。

临时保存失败与资料读取失败分开处理：前者保留运行中的状态，场景就绪后重试；后者暂停业务，保留原有资料。付款存储核对PaymentService请求的业务快照，收集阶段失败停止检查点提交，会话更换拒绝旧订单写入新槽位。仍未证明原生文件系统在进程崩溃时的原子性，也不能保证其他模组绕过保存入口的兼容性。

106项自动验证通过，含直接使用生产配置读取逻辑的测试。0.2.0编译及本机安装完成；三地图生成、真实现金支付与所有游戏交互仍待运行验收。说明见《三地图原型-0.2.0.md》，核查原始输出以`artifacts/inspection/continuation-`为前缀。

## 8. 0.3.0骑行表现核查

只读IL确认CharacterAnimationControl_MagicBlend构造时将`VehicleType`转为hash_Vehicle，其Update使用主角ridingVehicleType驱动整型参数；CA_ControlOtherCharacter启动时从目标载具vehicleAnimationType赋值，结束时清零。原生载具控制还会把玩家移动到车辆socket，本模组只适配视觉参数，不借用原控制动作或创建原生摩托。

CharacterAnimationControl_Moto支持轮组旋转与摩托音效，但与原生载具控制绑定，不直接挂到共享单车上。新车轮/踏板使用自行实现的位移计算。资源已经加载时从Moto关联载具读取姿态值；没有资源或对应Animator参数时保留原姿态，不猜测编号。

Movement.ForceTurnTo调整targetAimDirection及modelRoot旋转，不修改移动速度；CharacterModelAudioPoster.PostFootStepSound是步行脚步入口。新增补丁仅影响当前共享单车骑手。姿态退出恢复、空间检测和轮组动画代码已接入，125项自动验证通过；真实动画资源、贴合和Unity物理尚未运行验收。原始核查文件前缀为`artifacts/inspection/riding-`。
