# 创意工坊上传指南（1.0.16）

游戏自带上传器，不需要 Steamworks SDK、不需要 SteamCMD、不需要额外账号权限。
上传入口在**游戏内的模组界面**，上传的是 `Duckov_Data\Mods\DuckovSharedBike` 这个文件夹的全部内容。

下面所有行为都是反编译 `TeamSoda.Duckov.Core.dll` 核实过的（类型名写在括号里，方便以后游戏更新后复查）。

---

## 零、上传前必须满足的条件

1. **Steam 客户端在线**，登录的是**购买游戏的账号**。
   面板在 `SteamWorkshopManager.Instance == null` 或 `SteamManager.Initialized == false` 时会直接打日志
   `Cannot execute uplaod panel. SteamWorkshopManager and SteamManager are required.` 并且**什么都不显示**——
   也就是说"点了没反应"通常就是这一步没满足（离线模式、Steam 掉线、盗版/绿色版）。
2. **首次使用要同意工坊协议**：第一次打开模组界面会先弹协议面板（`ModManagerUI.agreementFadeGroup`，
   两个按钮 `agreementBtn` / `rejectBtn`）。点拒绝会 `AllowActivatingMod = false`，模组不能启用，
   上传按钮也不会工作。
3. Steam 账号需已同意 **Steam 创意工坊法律协议**（Steam 客户端首次上传 UGC 时会要求，网页版
   账号 → 创意工坊 → 也是同一个协议）。
4. 模组已装好并且能正常加载（`mod\info.ini` 的 `name` 必须等于 dll 文件名前缀：
   `name=DuckovSharedBike` ↔ `DuckovSharedBike.dll`）。

## 一、准备文件夹（30 秒）

```powershell
scripts\Test.ps1        # 162/162
scripts\Build.ps1       # 产出 artifacts\DuckovSharedBike-1.0.16.zip
scripts\Install.ps1     # 安装到 Duckov_Data\Mods\DuckovSharedBike（需先关游戏）
scripts\Prepare-Workshop.ps1
```

`Prepare-Workshop.ps1` 做四件事：

- 逐个 SHA256 比对**已安装目录**与 `artifacts\package`，防止把旧构建传上去；
- 删掉 `DuckovSharedBike.pdb`（63KB，里面是本机绝对路径 `E:\javaproject\...`，对订阅者无用）；
- 删掉残留的 `logs` 目录，并警告任何计划外的文件（**上传是整目录打包，多一个文件就等于公开它**）；
- 打印将要上传的文件清单、版本号、封面尺寸、总大小，以及这次是"新建"还是"更新"。

当前结果：10 个文件、2.56MB、版本 1.0.16、封面 512×512。

## 二、在游戏里上传（点三下）

1. 启动游戏（Steam 在线）→ 主菜单 **模组 / Mods**（第一次进会先过协议面板）。
2. 找到 **共享单车** 条目。条目右侧有上传按钮（`ModEntry.uploadButton`）。
   显示条件是 `IsOwner(info) || !info.isSteamItem`——没上传过的本地模组一定显示。
3. 点上传按钮，弹出上传面板（`ModUploadPanel`）。面板里这些是**只读**的：

   | 面板项 | 来源 |
   | --- | --- |
   | 路径 | `ModInfo.path`（反斜杠已替换成正斜杠显示） |
   | 模组名 | `info.ini` 的 `name` |
   | 标题 | `info.ini` 的 `displayName` |
   | 描述 | `info.ini` 的 `description` |
   | 条目 ID | `publishedFileId`，没有就显示 `-` |
   | 封面 | 模组目录里的 `preview.png` |

   面板里的三个指示器（`indicatorNew` / `indicatorUpdate` / `indicatorOwnershipWarning` /
   `indicatorInvalidContent`）含义：
   - **新建**：`publishedFileId == 0`，这次会上传成一条全新条目；
   - **更新**：有 id，这次是更新已有条目；
   - **所有权警告**：Steam 认为你不是这条目的作者（换账号时才会出现）；
   - **内容无效**：`ModManager.TryProcessModFolder` 解析该目录失败，**上传按钮会被直接禁用**——
     这种情况下先修 info.ini（版本号、必填字段），别在面板里找原因。

4. 点 **上传**。进度条走完有两种结局：
   - 成功：面板重新读一次 `info.ini`，把新的 `publishedFileId` 显示出来，弹成功提示，
     `closeAfterSeconds` 秒后自动关面板；随后游戏会尝试用浏览器打开
     `steam://url/CommunityFilePage/{0}`（没弹出就手动去工坊"我的文件"里找）。
   - 失败：弹失败面板。多数是 Steam 侧问题（离线、协议未同意、Steam 客户端被拦截写入）。

上传器调用的是 `SteamWorkshopManager.UploadWorkshopItem(path, "")`：
**变更说明传的是空字符串**，所以工坊更新日志是空的。想留更新说明，只能在工坊网页上编辑条目描述。

## 三、上传之后（别跳过）

1. **把 id 抄回仓库**：

   ```powershell
   scripts\Sync-WorkshopId.ps1
   ```

   游戏把 id 写进的是**已安装目录**的 `info.ini`，仓库里的 `mod\info.ini` 不会自动变。
   不同步的后果是：下次别人（或换机器后的你）用仓库重新构建、上传，会**再新建一条重复条目**。
   `Install.ps1` 已经会在升级时保留已安装目录里的 id，所以同步一次就够。

2. **提交 `mod\info.ini`**（含 `publishedFileId=`）以及本次所有改动。
3. 工坊网页上补：缩略图/截图、更新说明、标签（游戏上传时会把标签硬写成 `Mod`，
   想要更细的分类只能在网页上改）、可见性（默认公开，可先设隐藏自测）。
4. 订阅一遍自己的条目，在干净存档上再跑一次租车流程——确认"订阅版本"和"本地版本"行为一致。

## 四、以后每次更新

```powershell
scripts\Test.ps1
scripts\Build.ps1        # 自动把 info.ini 版本写进 preview.png 的版本字样
scripts\Install.ps1      # 保留 publishedFileId
scripts\Prepare-Workshop.ps1
# 游戏内：模组 → 共享单车 → 上传（面板显示"更新"）
scripts\Sync-WorkshopId.ps1   # 一般不会有变化，跑一次确认
```

**不要**手动删除已安装 `info.ini` 里的 `publishedFileId`：删了就等于"下次上传新建条目"。

## 五、常见故障对照

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 点上传按钮毫无反应 | Steam 未初始化（离线/未登录/非 Steam 版） | 修 Steam 连接后重开游戏 |
| 面板弹出来但"上传"是灰的 | 显示"内容无效"，info.ini 解析失败 | 检查 `version`、`name`、dll 文件名是否等于 `name + .dll` |
| 每次上传都新建一条 | `info.ini` 里没有 `publishedFileId` | 上传后跑 `Sync-WorkshopId.ps1`，别把 id 弄丢 |
| 上传成功但工坊看不到 | Steam 后台还在处理 | 等几分钟刷新"我的文件" |
| 上传成功但玩家订阅后模组不加载 | 描述/标题里的反斜杠被 `Regex.Unescape` 吃掉，或 dll 缺失 | 描述里别写 `\`；本地删掉模组重装一次验证 |
| 上传报失败但网速正常 | 工坊法律协议未同意 / Steam 客户端拦截 | 客户端同意协议、重启 Steam |

## 六、本次上传结果（2026-11-06）

条目已建立：**3834463519**，2.686MB，2026-11-06 09:56 发布，作者账号即当前登录账号。

- 第一次点上传失败：`Failed to upload mod. Result:k_EResultFail`。原因是新条目刚 `CreateItem` 完就立刻提交内容，Steam 侧还没准备好。**对策：ID 拿到后等 1–2 分钟再提交，或失败后隔几分钟重试一次**。
- 第二次点上传成功：日志只有 `Upload result returned.`（无失败行），Steam 客户端日志出现
  `UGC Upload OK for file previewfile_3834463519.png`。
- 面板上的 `0 bytes / 0 bytes` 与"你可能没有更新此物体的权限"都不可信：整目录上传时 Steam 不上报字节进度；
  所有权判断在新条目上尚未刷新。**判断成功的唯一依据是日志里没有 `Failed to upload mod.`**。

仓库里已写入：

```ini
publishedFileId=3834463519
```

### 两个只能手工处理的点

1. **可见性默认是"仅限好友"**。条目页顶部横幅会写"当前可见性：仅限好友"，必须改成"公开"，
   否则别人搜不到。位置：Steam 客户端 → 社区 → 创意工坊 → 我的文件 → 该条目右侧菜单 → 更改可见性
   （或条目页面上的作者管理区）。
2. **标签 `Mod` 改不了**。它是游戏用 `SetItemTags` 硬编码写入的，普通账号没有 Steamworks 权限修改；
   页面上那行"体验优化 / 玩法 / 开发工具"也是游戏给的分类。别在标签上花时间。

## 七、家庭共享账号的限制（本次遇到）

本机情况：游戏来自**家庭共享**，当前登录账号 `76561198734723272` 并不拥有 app 3167020
（`steamapps\appmanifest_3167020.acf` 的 `LastOwner` 是 `76561199780777289`）。

后果：**可见性菜单里没有"公开"，只有"仅限好友 / 隐藏 / 非公开"。**
Steam 允许借库账号上传内容（我们确实传成功了），但不允许把非自己拥有的游戏的工坊内容公开发布。

三档可见性的实际效果：

| 选项 | 谁能看到 | 能订阅 |
| --- | --- | --- |
| 仅限好友 | 好友 | 能 |
| **隐藏**（unlisted） | **任何拿到链接的人** | 能 |
| 非公开 | 只有自己 | 不能 |

### 三条出路

1. **用拥有者账号发布（推荐）**。拥有者账号在这台机器上登录 Steam 即可，游戏本体与模组目录都不用搬：

   ```powershell
   # 先关游戏，再清掉属于借库账号的旧 id，否则会去"更新"一条没有权限的条目
   scripts\Clear-WorkshopId.ps1
   ```

   然后登录拥有者账号 → 启动游戏 → 模组 → 共享单车 → 上传 → 成功后 `scripts\Sync-WorkshopId.ps1`。
   条目从此归属拥有者账号，以后每次更新都要用那个账号。

2. **先用"隐藏"分发**。把链接贴到群里/贴吧/B站简介，别人点开就能订阅、能玩，只是搜不到。
   注意：借库账号发布的条目长期可能被 Steam 判定为非拥有者内容，不建议当作长期主链接。

3. **自己买一份**。在当前账号购入本体后，"公开"立刻出现，之后完全自主，不再依赖对方账号。

### 换账号重传前必看

- 必须先用 `Clear-WorkshopId.ps1` 清掉 `publishedFileId`，否则游戏会尝试更新旧条目并因权限不足失败
  （日志里是 `PublishFileId not match.` 与 `k_EResultFail`）。
- 旧条目 3834463519 记得在借库账号的"我的文件"里删除，避免两条并存。
- 换账号后把 [README.md](../README.md) 与本文档里的链接一并换成新 id。

## 八、让别人代我上传

自己账号是家庭共享、拿不到"公开"选项时，最省事的做法是**找一个拥有本体的朋友代传**，条目挂在他账号下。

### 8.1 打交接包

`powershell
scripts\Make-Handoff.ps1
`

脚本会从 `artifacts\package\DuckovSharedBike` 生成：

- `artifacts\handoff\DuckovSharedBike-HANDOFF-<版本>\DuckovSharedBike\` —— 正好 10 个文件（去掉 pdb、去掉 logs）
- 同目录 `HANDOFF-README.txt` —— 给代传者看的中文步骤，**故意放在模组文件夹外面**，不会被一起上传
- `artifacts\handoff\DuckovSharedBike-HANDOFF-<版本>.zip` —— 打包结果（1.0.17 约 0.9 MB），打印 SHA256

关键点：脚本会**删掉 info.ini 里的 publishedFileId**。留着它，对方的游戏会去"更新"你那条
3834463519，然后报权限错误失败。

### 8.2 发给对方

把 zip 直接发过去（QQ / 微信 / 百度网盘都行），或者让对方从 GitHub 仓库自己打包。
告诉他三件事：

1. 账号必须**拥有**《逃离鸭科夫》，Steam 在线；
2. 解压后把 `DuckovSharedBike` 文件夹放进 `...\Escape from Duckov\Duckov_Data\Mods\`；
3. 进游戏 → 模组 → 共享单车 → 上传按钮 → 等 3–5 分钟，成功后把条目链接发回来。

第一次上传如果日志出现 `Failed to upload mod. Result:k_EResultFail`，让他**再点一次**就行
（新建条目后 Steam 需要几秒准备，这不是配置错误）。

### 8.3 对方上传完

拿到条目 id 后写回仓库：

`powershell
scripts\Sync-WorkshopId.ps1 -ItemId <对方发来的 id>
`

`-ItemId` 是专门为"条目不在本机"准备的：不带这个参数时脚本只会从你本机已安装的
info.ini 里读，而对方账号上传的 id 不会出现在你的机器上。

### 8.4 之后的维护

- 条目归属对方账号，**Steam 不支持转移工坊条目所有权**，以后每次更新都要请他再传一次：
  你跑 `scripts\Build.ps1` → `scripts\Make-Handoff.ps1` → 把新 zip 发过去；
- 对方重放同样的步骤时，游戏会走"更新已有条目"分支，链接不变；
- 想随时收回自主权：自己买一份本体，用 `Clear-WorkshopId.ps1` 清 id 后重传一条自己的，
  再把 README/文档里的链接换成新 id。
