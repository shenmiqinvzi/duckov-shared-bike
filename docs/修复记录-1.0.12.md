# 1.0.12 修复记录：车在眼前却上不去

日期：2026-11-05
基线：1.0.11（黑化涂装版）

## 1. 现象

骑车过程中弹出"检测到位置跳转，已停止骑行"之类的提示，人被踢下车，车留在原处；之后走到车跟前按 F7，反复出现"车辆附近空间不足或地面已变化，请调整位置再上车"，车就在脚下也骑不上去。

两条提示其实是两个独立故障，只是经常连着出现：

- 骑行中的"位置跳转"判定（`LateTick`，`BicycleGeometry.MaxContinuousStep`）过于灵敏，把引擎自己的位移修正当成异常；
- 上车完成时的落点判定（`CompleteTransition`）条件叠加过严，正常停靠的车也会被判失败。

## 2. 骑行中被踢下车

`src/DuckovSharedBike/BikeWorldController.cs` 的 `LateTick` 每帧比较角色当前位置与上一帧位置，超过 `BicycleGeometry.MaxContinuousStep`（3 米）就结束骑行。3 米/帧的门槛看似宽松，但游戏自己会在这些情况下直接改写角色位置：

- 楼梯口与高差修正；
- 卡住时的脱困位移；
- 载具/旅行点附近的落位调整。

一旦触发，旧逻辑会 `SetRiding(false)`、`EndRiderPresentation()`，把车停在 `_lastRidePosition`。玩家和车从此分离，而且因为绕过了正常下车流程，玩家还站在车外几米处，接着就撞上第二个故障。

修复：跳跃距离 ≤ 15 米时不再结束骑行，而是把车（和地图标记）一起搬到角色新位置，姿态按新地面重算，本帧直接返回；只有 > 15 米才判定为真正的远程传送，仍按原逻辑结束骑行并提示。两条路径都写日志：

```
Ride position jump 4.3m, bike follows to x=... z=...
Ride ended after long jump 42.0m
```

## 3. 车在眼前却上不去

`CompleteTransition()` 上车分支原来是一串 `||` 串联的硬失败条件，任何一条不满足就整段放弃：

```csharp
if (Vector3.Distance(actor.transform.position,_bike.transform.position)>2.5f
    || !SafeGround.Clear(actor.transform.position,_bike.transform.position)
    || !SafeGround.Find(actor.transform.position,_bike.transform.position,actor,out var mountPosition)
    || Vector3.Distance(mountPosition,_bike.transform.position)>0.2f
    || (_settings.Riding.VehicleClearance && !BicycleClearance.Fits(...)))
```

逐条看为什么"正常停着的车"会失败：

| 判据 | 问题 |
| --- | --- |
| 距离 ≤ 2.5 米 | F7 之后要等 1 秒才执行，玩家这 1 秒继续走/跑几步就超了 |
| `SafeGround.Clear` | 从玩家头高向车射线，中间任何非玩家碰撞体（栏杆、草丛、树枝、木箱边角）都判失败 |
| `SafeGround.Find` 严格模式 | 要求 NavMesh 连通、落点周围 0.4 米胶囊完全空旷、地面法线 ≤ 35°、与 NavMesh 高差 ≤ 0.8 米。车贴墙、停在路缘、斜坡、树下、NavMesh 边缘，全部失败 |
| 落点距车 ≤ 0.2 米 | `Find` 会把候选点吸附到 NavMesh 或射线命中点，斜坡与台阶边缘上偏移几十厘米很常见，0.2 米等于要求"重新采样的点必须和车身完全重合" |
| `BicycleClearance.Fits` | 车体贴墙时必然失败，但车本来就是按同一套规则放下的，等于自我否决 |

修复（`src/DuckovSharedBike/BikeWorldController.cs`）：

1. **`SafeGround.Find` 增加 `relaxed` 重载**（`src/DuckovSharedBike/PrototypeAssets.cs`）。宽松模式：不吸附 NavMesh、法线阈值放宽到 58°、落点胶囊半径 0.22 米、跳过 NavMesh 连通性与 `Clear` 射线。严格模式的行为完全不变，召车与车辆生成仍走严格路径。
2. **上车改用宽松落点**：先取车身所在位置，偏移 > 0.9 米时在车身周围 8 个方向 0.55 米处找更近的落点，全部失败才提示。
3. **落点距离阈值**：0.2 米 → 0.9 米（水平距离，斜坡的高度差不算偏移）；上限 1.2 米。
4. **删除上车阶段的 `SafeGround.Clear` 硬失败**；F7 初检里只在距离 > 1.6 米时才要求视线无遮挡，贴着栏杆也能上车。
5. **`Fits` 降级为建议**：落点仍在车身 0.35 米内就记录 `Mount clearance advisory` 并继续，超过才拒绝。
6. **等待时间** 1 秒 → 0.35 秒，减少"按完 F7 又走开"的失败窗口。
7. **失败必留痕**：所有拒绝路径走 `FailMount(reason, message)`，日志写 `Mount rejected: <哪条判据>`，提示里带实际数值（例如"你离车还有 3.4 米"），不再是笼统的"空间不足或地面已变化"。
8. **下车同步放宽**：`FindLanding` 严格 8 方向失败后，再用宽松模式扫一遍，避免"车停在路缘却下不了车"。

## 5. 已知取舍

宽松落点意味着玩家可能被放到紧贴墙面的位置，角色碰撞体会与墙轻微重叠，游戏物理会自行挤出。相比"车在眼前上不去"，这个代价可以接受；真正需要保净空的是骑行移动，那部分仍由 `BicycleClearance.CanTravel` 以建议模式把关（`_clearanceWarned` 只警告一次）。
