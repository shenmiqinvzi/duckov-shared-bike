## 与完整设计的临时差异

1. **仅零号区的两处测试站点。** 它们用于跑通功能，并非最终入口/搜刮区/撤离路线布局；仓库区和农场镇尚未铺设。
2. **原型暂禁止未归还时切换主地图。** 当前地图的普通子场景通道可在下车后使用，车辆留原场景；正式跨地图留车恢复策略仍须验证实例生命周期后更新设计。
3. 自行车沿用玩家移动和碰撞，视觉模型跟随玩家，鸭子暂沿用原移动姿态；专用坐姿、踩踏动画与车辆尺寸碰撞尚未完成。
4. 账单以马蜂原窗口附加区域展示，不是塞入原物品包裹列表。保留“提取”付款语义和付款地点，并避免满仓库时无法结算。
5. 主动报失回收额外2000元仍是设计默认值，独立于已确认的死亡赔偿2000元。

这些差异标识原型范围，不把未经确认的新规则当作完整首版基线。后续以设计文档和实际验证结果调整。

## 付款保存方案

- 准备付款时生成操作ID，先保存待恢复订单。
- 现金扣款阶段暂阻止通过SavesSystem.SaveFile触发的中途保存，直到现金变化及回执均进入同一缓存检查点。
- 原生扣款使用现金开关，保存扣款前后余额。异常发生后可根据精确余额变化判定已扣、未扣或不确定；不确定不设为已支付。
- 回执及原生现金数据通过游戏保存链一起提交；再将订单结清并保存。
- 文件提交后从ES3.Location.File读回单车业务、世界数据和回执，避免把“缓存已写”误当“文件已写”。
- 重试同一操作ID读取回执并重新提交，不再次调用扣款。模组停用时只移除自己的Harmony补丁。
- 若其他模组直接绕过SavesSystem写存档，或在现金扣款回调中切换存档、重写现金，不能宣称已兼容；实际游戏文件恢复和崩溃故障注入尚未验收。不确定回执保留用于核查，不盲目再次扣钱。

## 你方便时再测试

1. 完整重启游戏，启用“共享单车（骑行原型）”，用测试存档进入零号区。
2. 寻找绿色站点或地图上的单车标记，靠近按 **F6** 打开租还面板；原游戏交互键也提供入口。
3. 点击租赁，靠近车按 **F7** 上车；走一段，再按F7下车。比较高负重和零负重移动速度，尝试骑行吃药、射击和冲刺。
4. 把车带到另一站点，F6打开面板并归还。未归还时尝试撤离应被拦截；还车后应允许正常撤离。
5. 回地堡打开马蜂，查看右侧单车账单，点击“提取并支付”。验证不足现金和足额现金两种情况。
6. **F8**打开报失确认；确认会回收车辆并加2000元回收费，取消继续租赁。死亡赔偿另用一轮测试。
7. **F9**显示/隐藏诊断；**F10**记录当前场景及位置。笔记本功能键可尝试配合Fn。

本次不要求立即试玩。实际结果与设计不符时，以日志和具体复现步骤修正，而不把编译成功当作游戏验收通过。
