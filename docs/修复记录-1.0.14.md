# 1.0.14 修复记录：骑行中受伤立刻下车

日期：2026-11-05
基线：1.0.13（F 键上下车）

## 1. 需求

骑行过程中受到伤害时直接下车，不要有延迟。

原来的上车/下车都走 0.35 秒的过渡（`_transitionUntil`），那是为了掩盖姿态切换的突兀。但挨打这件事不能等：玩家还坐在车座上等过渡，下一发子弹已经到了。

## 2. 怎么判定"受到了伤害"

游戏里伤害最终都会落到角色的 `Health` 组件上（`TeamSoda.Duckov.Core.dll`，全局命名空间，类型名就叫 `Health`），核心方法是：

```csharp
public bool Hurt(DamageInfo damageInfo)
```

朴素做法是直接给 `Hurt` 打前缀、无条件下车。问题是 `Hurt` 被调用不等于真的掉血：

- 无敌帧内的调用；
- 伤害被护甲完全吸收；
- 伤害数值为 0 的触发型调用（中毒 tick、环境判定）。

这些都会让玩家莫名其妙被甩下车。所以用**调用前后血量对比**做判据：

```csharp
private static void HurtPrefix(Health __instance,out float __state)
    => __state = __instance!=null ? __instance.CurrentHealth : -1f;

private static void HurtPostfix(Health __instance,float __state)
{
    if (__instance==null || __state<0f) return;
    // 只认真正掉血的伤害：无敌帧、完全被护甲吸收的调用不触发下车。
    if (__instance.CurrentHealth>=__state-0.0001f) return;
    World?.OnRiderDamaged(__instance);
}
```

`-0.0001f` 是浮点容差，避免血量因舍入没变却被判成掉血。这个方法不修改 `Hurt` 的返回值，也不改变原方法的任何行为。

## 3. 为什么不在回调里直接下车

`Hurt` 是在伤害结算的调用栈里跑的，栈上可能正持有角色状态、动作系统、受击动画。在这个位置调用 `EndRiderPresentation()` 销毁姿态对象，很容易和游戏自己的受击流程打架（轻则姿态错位，重则动作系统抛异常）。

所以回调只做两件事：判定、置标志。

```csharp
// Tick() 的 try 第一行
if (_damagedPending && Time.timeScale>0) { _damagedPending=false; ForceDismountOnDamage(); }
if (Transition && Time.unscaledTime>=_transitionUntil && Time.timeScale>0) CompleteTransition();
```

放在 `Tick()` 开头、`CompleteTransition()` 之前，保证：

- 同一帧内完成下车（感知延迟 < 1 帧，约 16ms，主观上就是"立刻"）；
- 如果伤害发生在过渡期间，会先下车，过渡条件随后自然失效；
- `Time.timeScale>0` 的判断避免在暂停/对话/过场里执行位移。

`_damagedPending` 只置一次，连续受击（比如被连射）不会重复触发。

## 4. 下车做了什么

`ForceDismountOnDamage()`（`src/DuckovSharedBike/BikeWorldController.cs`，`FailMount` 之后）：

1. 取当前骑手与租约；任一为空或已不在骑行状态就直接清空 `_rider` 返回；
2. `FindLanding(actor,out landing)` 找安全落点，失败则退回角色当前位置（宁可原地放下，也不要因为找不到落点把人留在车上）；
3. `CapturePose()` 复位姿态；
4. `SetRiding(vehicleId,false)` 结束骑行状态；
5. `EndRiderPresentation()` 拆掉骑手与车的挂接；
6. 清空 `_rider / _returnAfterDismount / _transitionUntil / _mounting`；
7. `actor.SetPosition(landing)` 把人放到落点；
8. 日志 `Forced dismount on damage at x=.. z=.. health=..`，提示「受到伤害，已立刻下车；车辆留在原地，租赁继续计费。」

车辆不回收、不挪位，租赁继续计费——这和普通下车的语义一致，玩家可以走回去再骑。

## 5. 边界

| 情况 | 行为 |
| --- | --- |
| 伤害把血量打到 0（死亡） | `OnRiderDamaged` 里 `IsDead` 检查直接 return，死亡流程仍由 `NativeRentalRuntime.OnDeath` 负责（赔车、退租、结算） |
| 无敌 / 护甲完全吸收 | 血量没变，不触发 |
| 持续伤害（中毒、流血） | 第一次掉血就下车，之后 `IsRiding` 为 false，不会再触发 |
| 非玩家角色受伤 | `health!=actor.Health` 直接 return，只认玩家自己的 `Health` |
| 不在骑行中受伤 | `IsRiding` 为 false，不触发 |
| 暂停 / 过场中受伤 | `Time.timeScale>0` 挡住，恢复后下一帧处理 |

## 7. 可调项

如果觉得"被打一下就下车"过于敏感，可以在 `OnRiderDamaged` 里加血量比例阈值，例如只在下血量超过最大值 5% 时触发：

```csharp
if (health.MaxHealth>0f && (__state-health.CurrentHealth) < health.MaxHealth*0.05f) return;
```

当前版本按需求取最严格语义：只要掉血就下车。
