# 首次游戏内验证：加载测试版0.0.1

这次只验证游戏能否加载我们编译的模组，以及诊断面板、快捷键和跨场景读取是否正常。用一个测试存档进入地堡即可，不需要开始正式搜刮。

## 1. 安装位置

安装包：`E:\javaproject\duckov-shared-bike\artifacts\DuckovSharedBike-0.0.1.zip`。

目标目录：

```text
E:\Steam\steamapps\common\Escape from Duckov\Duckov_Data\Mods\DuckovSharedBike
```

目录内应直接看到：

```text
DuckovSharedBike.dll
DuckovSharedBike.pdb
info.ini
preview.png
```

如果尚未自动安装，先退出游戏，把ZIP里的 `DuckovSharedBike` 文件夹复制到游戏的 `Duckov_Data\Mods` 下。没有 `Mods` 时可以创建。不要形成 `Mods\DuckovSharedBike\DuckovSharedBike` 的双层目录。

## 2. 你需要做的操作

1. 完整启动游戏，在主界面/设置中找到原游戏的Mods模组管理入口。
2. 找到 **“共享单车（加载测试版）”** 并启用。首次使用模组时，按游戏自身提示完成模组协议流程。
3. 应看到左上角面板：**“共享单车 · 加载测试 v0.0.1”**，并显示 **“状态：模组已加载”**。
4. 按一次 **F9**：面板隐藏；再按一次：重新显示。笔记本若F键用于多媒体功能，可尝试Fn+F9。
5. 进入测试存档的地堡，观察“玩家位置”从等待提示变为X/Y/Z坐标，走几步后坐标应变化。当前场景显示内部英文名称属于正常现象。
6. 按 **F10**（必要时Fn+F10），把当前位置和已加载场景写入日志。
7. 若方便，可进入零号区验证面板继续存在，坐标和场景正常更新，再按F10记录一次。
8. 返回主界面，在模组管理中停用本模组，面板应消失；重新启用后应恢复，不出现叠加的多个面板。

## 3. 把结果告诉我

按实际情况反馈：

```text
模组菜单：能找到 / 找不到
启用后：有面板 / 没面板 / 有报错
中文：正常 / 方框或乱码
F9：正常 / 无效
进入地堡：位置会变化 / 不变化
进入零号区：正常 / 面板消失 / 暂未测试
停用再启用：正常 / 面板残留 / 暂未测试
```

不需要看懂代码。截图和报错文字可以直接发在聊天中。

## 4. 日志位置

模组日志：

```text
E:\Steam\steamapps\common\Escape from Duckov\Duckov_Data\Mods\DuckovSharedBike\logs\bootstrap.log
```

其中 `Enabled version=0.0.1` 表示游戏实际调用了模组启用入口；`Manual snapshot` 表示F10记录成功；`Disabled version=0.0.1` 表示停用清理已执行。

只有游戏真正加载本模组后，日志目录和文件才会生成。尚未进入游戏时没有日志是正常现象。若文件记录不可用，模组还会把消息写入原游戏日志，前缀为 `[DuckovSharedBike]`。

## 5. 本版功能边界

当前可见的是开发诊断面板，暂时没有站点、可骑自行车和马蜂账单。本版不修改玩家速度、现金、背包或租赁存档。完成加载验证后再实现两个测试站点和租还原型。
