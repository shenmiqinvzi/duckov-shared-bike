# 鸭科夫共享单车 MOD

当前版本：**1.0.8 付费召车版**（2026-10-29）。在 1.0.7 自动扣款的基础上，新增 F5 付费召车（¥100，自行车从最近站点驶来，默认 15 秒送达，可配置 `Summon.Cost`/`Summon.Seconds`/`Keys.Summon`）与程序合成音效（扣款成功叮、余额不足低鸣、租车/召车/送达提示音，`Ui.Sounds` 可关）。适配本机 Windows Steam《逃离鸭科夫》2.3.30，build 24013657，Unity 2022.3.62f2；单人游戏。游戏内复验仍未完成。

## 功能总览

- **站点租车网络**：地图上九大共享单车站点（绿色醒目标记+巨型P字灯箱+悬浮信标），靠近站点按 F6 租车，任意站点按 F 还车。
- **付费召车（F5）**：不在站点旁时花 ¥100 把最近站点的车召唤到身边，约 15 秒从站点方向驶来，落点自动找安全位置；召车费/延迟/快捷键均可配置。
- **骑行无视负重并加速**：骑行时负重量按零负重计算（负重减速 Buff 完全剔除），并额外加速 ×1.5（默认，可配 0.5–2.0）。
- **自动扣款**：还车、报失（F8）、系统回收时立即自动结算（租金 200元/小时，不足 1 小时按 1 小时；报失含 ¥2000 回收赔偿），不再需要去马蜂自提点排队付款。
- **死亡兜底**：角色死亡回收车辆不自动扣款（死人无法动账），复活后在站点或马蜂自提点补付即可，账单金额不变。
- **现金不足补付**：余额不够时订单保持待付款，可在任意站点还车时自动补扣，或到马蜂自提点点击"补付账单"，金额与幂等保护不变、不会重复扣钱。
- **音效反馈**：扣款成功"叮"、余额不足低鸣、租车/召车/送达提示音，全部运行时程序合成（零外部音频资源），`Ui.Sounds=false` 一键关闭。
- **防丢车持久化**：车辆位置与订单状态随存档原子写入，切地图、换场景、重开游戏后车辆原位恢复；存档校验失败自动走系统回收，不吞车不吞钱。
- **美化醒目**：自行车带发光条纹/大灯/尾灯/警示旗，站点带描边停机坪/四角灯柱/P字灯箱/旋转信标，远处一眼可见。

## 开始试玩

日常游玩不需要编译。安装完成后，重启游戏，在模组菜单启用“共享单车”。进入零号区，打开地图寻找绿色站点标记，靠近后 F6 租车、F7 上下车。在任意站点归还后立即自动扣款；报失/系统回收同样自动扣款。现金不足或扣款会话不可用时订单保持待付款，可在马蜂自提点右侧账单点击“补付账单”，或下次还车时自动补扣。不在站点旁时按 F5 付费召车：先扣 100 元，车从最近站点方向驶来约 15 秒送达；落点不安全或租赁失败会自动退款。

## 1.0.8 付费召车说明

- 按 F5（可配置）发起召车：要求无在租车辆、有租车资格、本地图本场景存在站点；先经 `DirectPay` 原子扣款 100 元召车费，失败（含现金不足）立即中止并低鸣提示。
- 扣款成功后播放三连叮，随后锁对应订单按正常 `RatePlan` 建立（200元/小时，不足1小时按1小时），自行车以幽灵车动画从最近站点位置驶向玩家附近 1.6 米安全落点（8 方向 `SafeGround.Find` + 车体净空检查），默认 15 秒（1–120 可配）。
- 送达后落地成真车、响租车音、持久化车辆 pose；落点不安全或租赁建立失败会自动 `DirectRefund` 退款。
- 召车途中切场景/子场景/换存档槽：订单保留，车辆 pose 指向召车落点，`SyncWorld` 恢复时正常生成；扣掉的召车费不退（车已按落点保留）。
- 音效为运行时按采样合成的 AudioClip（无外部资源），`Ui.Sounds=false` 可整体关闭；扣款成功与余额不足的声音在自动结算与马蜂补付两条路径都生效。

## 1.0.7 自动扣款说明

- 还车成功后立即用同一事务扣款：现金足够则提示“本次费用X元已自动扣款”，订单直接进入已付款历史，恢复租车资格。
- 报失（F8）与系统回收同样自动扣款；死亡回收保持原状（角色已死无法保存现金，复活后可补付）。
- 扣款条件比马蜂面板宽松：不再要求在地堡或打开马蜂自提点窗口，只要当前场景允许保存人物现金（非加载中、SaveCharacter 开启、宠物现金可保存）就结算。
- 现金不足或会话不可用时订单保持待付款，租金与赔偿金额不变；可在马蜂自提点补付，或下次还车时自动补扣。
- 付款事务、回执与幂等保护与 1.0.x 完全一致，自动扣款不会重复扣钱。

## 1.0.4 骑行速度说明

- 设计基线是“**骑上后按零负重计算**”，不是“在零负重基础上再加速”。游戏里只有负重比例超过轻载阈值（约 25%）才会挂上负重减速 Buff；没到阈值时，零负重速度和当前速度相同，骑行不会变快。
- 上车提示会显示：`速度按零负重计算（负重 12.3/40.0）`；F9 面板新增“速度：步行 4.20｜骑行 4.20｜负重 …”，可以直接看到补丁前后的数值。
- 日志新增：`Mounted speed patched=... native=... weight=.../... buffs=Weight_Heavy ... multiplier=1`。如果 `patched` 和 `native` 相同且 `buffs` 为空，说明当前没到减速档，不是补丁失效。
- 如果希望单车本身比步行更快，把 `mod/prototype.json` 的 `Riding.RideSpeedMultiplier` 改成 `1.15` 或 `1.25`；默认 `1.0`，严格保持“只消除负重减速”。

## 1.0.3 修复：还车后找不到返回通道

- 原生隧道/井盖是 `InteractableBase`；模组站点交互物离得近时会抢同一个交互提示。现在玩家站在原生传送点 3.5 米内时，共享单车提示自动让位。
- 欠车时不再等传送交互完成后再拦截 `DoTeleport`（那样可能把一次性传送点消费掉），而是直接在 `InteractableBase.StartInteract` 阶段拒绝，并记录 `Teleport blocked ...`；还车后传送点仍是可用的。
- 屏幕标签新增最近的“返回通道”及距离（最多两个），不依赖地图标记。
- F9 面板新增“脱困：重新启用附近通道”按钮，可重新启用 30 米内被禁用/碰撞体关闭的原生传送点。
- 新日志：`Native travel point ... enabled/collider/disableOnFinish`、`Shared-bike prompt suppressed ...`、`Teleport blocked ...`。

## 1.0.2 改进

- **启动原生契约自检**：检查本模组依赖的类型、方法、私有字段、UI、存档和 POI 接口。游戏更新导致不匹配时不再“带病加载”，而是禁用功能并在 F9 面板和日志里列出缺少项。
- **周期存档降频**：租赁期间的完整原生存档从每 5 秒改为每 20 秒（可在 `prototype.json` 调整 5–300 秒）；上车、还车、付款、死亡、退出仍立即保存。失败重试仍为 5 秒。
- **按键可配置**：`Keys` 段可把 F6–F10 换成其他按键（例如笔记本没有独立功能键时）；解析失败会记日志并回退默认值。
- **账单面板可换边**：`Ui.InvoicePanelSide` 可选 `right`/`left`，避免压住原游戏右侧栏；`Ui.ShowWorldLabels` 可关闭屏幕站点标签。
- **诊断面板**：F9 现在显示原生契约状态、模型层/部件数、存档频率和当前按键。
- **细节**：GUI 样式不再每帧新建；自行车地图标记会跟随车辆；租车/还车/回收都写入日志。

## 1.0.1 修复的三处问题

- 站点和车体模型不可见：运行时创建交互组件触发原生 `InteractableBase.Awake` 空引用；原实现只靠 `Shader.Find` 建材质，构建版找不到 shader 时部件没有材质可画。现在交互触发器独立成子物体，材质改为克隆游戏自身材质，模型按相机可见层放置；站点名称和距离也会直接画在屏幕上。
- 上车后不能移动：交互动作因上述空引用永远不会完成，而原生交互动作 `CanMove()` 恒为 false，角色被锁死；旧的空间检查还会每帧把玩家拽回原位。现在骑行时拦截并清理会锁移动的动作，车体空间检查只提示、不再回写位置。
- 账单支付歧义：模组一直是单击账单直接扣款（存档中两笔都是单次操作完成）。按钮改为“提取账单并支付”，并补充“点击账单即扣款”的说明；原游戏自提点的物品“提取”按钮与单车账单无关。

## 已实现的首版功能

- 零号区、仓库区、农场镇各三处规划站点，按本机游戏地标在安全地面寻位，位置随当前存档保存，含站点和自有车辆地图标记。
- 自行车实体、轮辐与踏板转动、默认鸭子骨架坐姿、握把与踩踏，1秒上下车、临时停车和异站归还，坡面朝向及车体空间检查。
- 骑行只排除负重速度惩罚，保留真实重量及其他速度状态；拦截战斗、冲刺、食药、拾取和丢弃操作。
- 欠车禁止正常撤离及新租赁，欠费禁止新租赁。普通子场景通道需下车，无法保证返回的跨区通道需先还车。
- 每个开始的小时200元，最低200元；停车继续计时，暂停、加载和离线不计时。死亡回收额外2000元，报失确认、系统无罚款回收。
- 地堡马蜂原窗口旁的专用订单面板、现金付款、余额不足提示、已付款历史。账单不生成占格物品。
- 原生存档隔离、停车读档恢复、5秒周期保存、失败重试、现金回执和订单去重；当前原生存档提交使用整体文件替换及上一份完整存档备份。

## 验证边界

161/161项自动化测试通过；其中包括500组实际游戏Stat计算对照、1000组双骨骼几何输入、付款三个保存阶段前后中断的文件恢复测试，以及运行配置与速度倍率校验。目标游戏程序集编译为0警告、0错误。

1.0.0 实际启动过游戏（10-14 至 10-19 的日志与存档可查），但反馈的三个问题说明首轮“能加载”不等于“能玩”。1.0.1 的修复来自日志、程序集 IL 与存档回执的交叉核对，仍需重新进游戏确认模型可见、上车可走、付款一次完成。安装包及工具不包含游戏程序集或游戏素材。

## 开发维护

```powershell
.\scripts\Test.ps1
.\scripts\Build.ps1
.\scripts\Install.ps1
```

默认游戏目录为 `E:\Steam\steamapps\common\Escape from Duckov`。安装脚本先检查游戏已退出，再备份并更新本模组的10个文件，逐一核对SHA256，保留日志。
